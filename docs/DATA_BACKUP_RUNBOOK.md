# BISS Studio — נוהל גיבוי נתונים

עודכן: 10 בנובמבר 2026

## שכבות הגיבוי

1. **קוד ותיעוד:** GitHub `main`.
2. **פריסה:** היסטוריית Vercel של פרויקט `biss-studio`.
3. **נתונים:** Supabase המבודד `nqpxgxoxxafsrmvfrqnh` ותמונת נתונים פרטית.
4. **חבילת המשכיות מקומית:** ZIP מאומת ו-manifest בתיקיית `backups/`, הנמצאת תחת OneDrive. יש לוודא בנפרד שלקוח הסנכרון פעיל ושהקובץ עלה לענן.

אין שכבה אחת שמחליפה את האחרות. Vercel אינו גיבוי למסד, GitHub אינו כולל נתוני אמת, ותמונת JSON אינה כוללת משתמשי Auth או סודות.

כוללת:

- מלאי ציוד ותרגילים
- פריטי שיתוף
- קבוצות, מפגשים, התאמות והעברות

אינה כוללת:

הקובץ כולל שם ואימייל של מנהל והערות שעשויות להיות רגישות. הוא מוחרג כולו מ-GitHub, ויש להצפין כל עותק שיוצא מהמחשב/OneDrive המוגן.

## מה נכנס ל-ZIP ההמשכיות

נכנסים:

- כל קוד המקור והתיעוד
- `CONTINUITY.md`, `SUCCESSOR_START_HERE.txt` ו-`.env.example`
- קובצי SQL בספריית `supabase/`
- בדיקות ודוח QA
- תמונת הנתונים הפרטית שנבחרה במפורש

לא נכנסים:

- `.git`, `node_modules`, `.next`, `.pnpm`, `.pnpm-store`, `.vercel`
- כל `.env` או `.env.*`, למעט `.env.example`
- ZIP קודמים
- סודות, PIN/hash, מפתחות API, קודי 2FA וצילומי מסך שלהם

לאחר יצירה פותחים את ה-ZIP מחדש, בודקים שקבצי ההמשכיות והסכימה קיימים, מחשבים SHA-256 ושומרים manifest לידו.
